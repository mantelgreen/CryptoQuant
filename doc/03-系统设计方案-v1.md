## 1. 产品定位与设计原则

**定位**：面向个人 / 小团队研究员的「数字币一站式研究平台」，把「数据 → 因子 → 策略 → 回测 → 模拟盘 → LLM 复盘」串成一条流水线，差异化点是 **LLM 驱动的因子研究、策略生成、模拟交易决策** 以及 **三路绩效对比**（手动 / 策略化 / LLM）。

**设计原则**：
1. **数据优先**：所有功能建立在干净的 TimescaleDB 历史库之上，没有数据就没有策略。
2. **白盒 + 可追溯**：每一份策略、因子、回测、模拟订单都可追溯到代码版本与运行参数。
3. **异步为默认**：长任务一律走任务队列；LLM 调用一律异步 + 流式回执。
4. **适配器抽象**：交易所 / LLM / 因子源都可替换，未来切 OKX / DeepSeek 不用改业务。
5. **组件复用**：前端公共组件 ≥ 60% 跨页面复用；后端 `core/` 不允许反向依赖 `features/`。

### 6.3 关键 Hypertable 与索引
```sql
-- klines
SELECT create_hypertable('klines', 'open_time', chunk_time_interval => INTERVAL '7 days');
CREATE UNIQUE INDEX ux_klines ON klines (symbol, interval, open_time);
CREATE INDEX ix_klines_symbol_ts ON klines (symbol, open_time DESC);

-- factor_values
SELECT create_hypertable('factor_values', 'ts', chunk_time_interval => INTERVAL '30 days');
CREATE UNIQUE INDEX ux_factor_values ON factor_values (factor_id, symbol, ts);

-- sim_positions
SELECT create_hypertable('sim_positions', 'ts', chunk_time_interval => INTERVAL '7 days');

-- llm_usage
SELECT create_hypertable('llm_usage', 'ts', chunk_time_interval => INTERVAL '1 day');
CREATE INDEX ix_llm_usage_model ON llm_usage (model, ts DESC);
```

### 6.4 Continuous Aggregates
```sql
CREATE MATERIALIZED VIEW klines_5m  WITH (timescaledb.continuous) AS
SELECT symbol, time_bucket('5 minutes', open_time) AS bucket,
       first(open, open_time) open, max(high) high, min(low) low, last(close, open_time) close, sum(volume) volume
FROM klines WHERE interval='1m' GROUP BY symbol, bucket;
-- 同样：15m/1h/1d 物化视图，从 1m 聚合
```

### 6.5 pgvector 用法
- `factor_library.embedding vector(1536)` —— 因子描述 embedding，用于「相似因子检索」
- `strategies.embedding vector(1536)` —— 策略描述 embedding
- 不存放行情向量。

## 8. 模块设计

### 8.1 数据模块 (`data/`)
- `BinanceKlineFetcher`：限速客户端；任务 `download_klines(symbol, interval, start, end, mode=full|incremental)`
- 增量模式：读 Redis `last_bar:{symbol}:{interval}`，无则查 DB `max(open_time)`。
- 完成后写 `last_bar`，并触发 `klines_5m` refresh（连续聚合自动）。

### 8.2 行情模块 (`market/`)
- `StreamHub` 单进程负责：
  - 维护到 Binance WS 的 N 个连接（按 symbol 前缀分组）
  - 解析后 publish 到 `ws:market:{symbol}`
- `MarketWsRouter`（FastAPI）：
  - 客户端订阅时 `SUBSCRIBE ws:market:{symbol}`
  - 100ms 节流后下发
- 心跳：30s ping/pong，断线重连指数退避。

### 8.3 策略模块 (`strategy/`)
- 事件引擎五层：`Signal → Order → Fill → Portfolio → Metric`
- **快速通道**：`vectorbt` 包装，输入 `close, signal`，输出 `pf.stats()`
- **生产通道**：自研事件引擎，含：
  - 撮合：现价 / 下根开盘 / 限价单撮合
  - 滑点：默认 `0.05%` × vol；可配
  - 手续费：默认 `0.1%` (Binance 现货币币 VIP0)
  - 风控：单笔 / 单日 / 最大回撤
- 指标卡：年化、夏普、Sortino、Calmar、最大回撤、胜率、盈亏比、换手率、Alpha、Beta。
- 归因：按 symbol × 方向拆分贡献。

### 8.4 因子模块 (`factor/`)
- `FactorRegistry`：启动时扫描 `@register_factor` 装饰器，注册元数据 + docstring + tags + 单元签名 `(df: pd.DataFrame, params: dict) -> pd.Series`。
- **ML 流水线**：
  1. 选定 symbols × 时间窗 × 颗粒度
  2. 选定 N 个因子 → 拉取数据 → 对齐 → 标准化 → 去极值 → 中性化（可选）
  3. 切分 train/val/test（时间序列切分，禁用未来函数）
  4. 训练：默认 LightGBM（轻）/ PyTorch MLP（重）；可选 Transformer 序列模型
  5. 输出：IC / RankIC / 因子衰减 / 因子相关矩阵 / 测试集回测曲线
- **AI 因子工坊**：Agent 接收用户自然语言目标 → 调用工具检索候选因子 → 生成新因子代码 → 在隔离 sandbox 执行 → 通过校验（白名单算子、shape check、nan 比例）→ 入库候选。
- 沙箱：`RestrictedPython` + 算子白名单 + 内存/时长上限。

### 8.5 LLM Agent 模块 (`agent/`)
- 三类 Agent（基于 AgentScope）：
  - **FactorAgent**：自然语言目标 → 因子草稿 → 校验 → 回测 → 报告
  - **StrategyAgent**：自然语言策略 → 策略代码草稿 → 回测 → 报告
  - **TraderAgent**：周期读市场快照 + 持仓 → 出 `decision_json`（symbol, side, qty, reasoning）
- 工具集：
  - `get_market_snapshot(symbol)`
  - `list_factors(filter)`
  - `run_backtest(spec)`（异步起任务，返回 job_id）
  - `get_backtest_result(job_id)`
  - `submit_sim_decision(decision_json)`
  - `search_similar_factors(query)`（pgvector 余弦）
- **决策安全闸**：所有 LLM 产出的下单决策必须经过 `RiskGuard` 校验（最大持仓、单笔限额、当日亏损上限）。

### 8.6 模拟交易 (`simtrader/`)
- 三类账户：`manual` / `strategy` / `llm`
- 撮合：
  - 默认「下一根 K 线开盘价」撮合，可改「最新价」
  - 支持限价单（挂在订单簿）
- 持仓：cash + positions(symbol→qty, avg_price)，按 mark-to-market 估值
- 报告：账户净值曲线、回撤曲线、订单列表、成交列表、月度收益热力图

### 8.7 LLM 用量统计 (`llm/usage.py`)
- 每次 LLM 调用记录 `(ts, model, provider, prompt_tokens, completion_tokens, total_tokens, cost_usd, caller, latency_ms)` 到 `llm_usage` hypertable。
- 定时任务（每 5 分钟）按 `model × caller × hour` 聚合到 `llm_usage_hourly` 物化视图。
- 前端 `/analytics/llm` 页：今日 / 本周 / 本月 / 模型分布 / 调用方分布 / 成本曲线。

## 11. LLM Agent 与 Token 统计

### 11.1 Token 记录点
- LLM Client 统一封装 `_call(provider, model, messages, **kwargs)`，出口处记录 token（响应 usage 字段）+ 计算 cost。
- 没有 usage 字段时按 `len(text)/4` 估算（标注 `estimated=true`）。

### 11.2 汇总与计费
- 物化视图 `llm_usage_hourly(model, hour, prompt_tokens, completion_tokens, total_tokens, cost_usd, calls)`
- 物化视图 `llm_usage_daily_by_caller(model, day, caller, ...)`
- 币种 / 用户 / Agent 维度可后续按 `caller` 拆分。

### 11.3 AgentScope 集成
- `AgentScopeService` 包装 `agentscope.ReActAgent` / `agentscope.MsgHub`
- 工具函数位于 `agent/tools/`，每个工具 `@tool` 标注 schema、权限、超时
- Prompt 模板位于 `agent/prompts/{zh,en}.yaml`
- 决策 JSON 由 Agent 输出固定 schema：`{action: "open"|"close"|"hold", symbol, side: "long"|"short", qty, leverage, reasoning}`

## 13. 限速与反封 IP（落地为 `core/rate_limit.py`）

- **令牌桶**：Redis 脚本实现滑动窗口（`INCR + EXPIRE`），可多机共享。
- **客户端适配**：`BinanceRestClient` 装饰器 `@with_rate_limit(weight=2)`。
- **熔断**：响应 429/418 → `BreakerOpen` 状态 60s，期间所有请求直接拒绝。
- **IP 轮换**（v1.1）：支持 `proxy_pool` 配置，预留接口。
