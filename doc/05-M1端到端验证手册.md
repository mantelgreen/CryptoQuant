# M1 端到端验证手册

> 目标：在能访问 `192.168.71.110:5432 / 6379` 与 `api.binance.com` 的机器上，把 M1 数据闭环完整跑通：
> - 启动 gateway + ARQ worker
> - 提交一次 BTCUSDT 1m K 线下载任务
> - ARQ worker 真实从币安拉数据入库
> - 通过 `/api/v1/data/klines` 查回数据
> - 前端打开 `/data/downloads` / `/market/BTCUSDT` 看到 K 线
> - `/ws/market` 实时推送

## 0. 前置检查

```bash
# 数据库 / Redis 已起来（你的本机就是）
python -c "import asyncio, asyncpg; asyncio.run(asyncpg.connect(host='192.168.71.110', port=5432, user='root', password='123456', database='cryptoquant_db').close()); print('pg ok')"
python -c "import asyncio, redis.asyncio as r; c=r.from_url('redis://192.168.71.110:6379/8'); asyncio.run(c.ping()); print('redis ok')"

# 币安可达
curl -s -o /dev/null -w "binance:%{http_code}\n" "https://api.binance.com/api/v3/ping"
```

## 1. 安装依赖

```bash
cd backend
pip install -e ".[dev]"          # 已包含 arq / sqlalchemy / asyncpg / redis / httpx / websockets / pydantic-settings ...
```

## 2. 确认迁移已应用（首次必须）

```bash
cd backend
$env:DATABASE_HOST="192.168.71.110"
$env:DATABASE_USER="root"
$env:DATABASE_PASSWORD="123456"
$env:DATABASE_NAME="cryptoquant_db"
$env:REDIS_HOST="192.168.71.110"
$env:REDIS_DB="8"
python -m alembic upgrade head
# 期望：Running upgrade -> 0001_m1_initial, ...
```

## 3. 启动 gateway

```bash
# 终端 1
cd backend
$env:DATABASE_HOST="192.168.71.110"
$env:REDIS_HOST="192.168.71.110"
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
# 期望看到：streamhub.started streams=10
```

## 4. 启动 ARQ worker

```bash
# 终端 2
cd backend
$env:DATABASE_HOST="192.168.71.110"
$env:REDIS_HOST="192.168.71.110"
arq app.job.arq_app.WorkerSettings
# 期望看到：Starting worker for queues: data
```

## 5. 端到端冒烟

```bash
# 1. health
curl http://localhost:8000/health
# 期望：{"code":"OK","data":{"db":true,"redis":true,...}}

# 2. 提交下载任务（拉最近 1 天 1m K 线）
curl -X POST "http://localhost:8000/api/v1/data/downloads?symbol=BTCUSDT&interval=1m&start=2025-09-06T00:00:00Z&end=2025-09-07T00:00:00Z&mode=full"
# 期望：{"code":"OK","data":{"job_id":"<uuid>","status":"queued"}}

# 3. 看任务状态（应从 pending -> running -> succeeded）
curl "http://localhost:8000/api/v1/data/downloads?limit=5"
# 期望：downloaded_bars 由 0 增长到 1440 左右（24h × 60min）

# 4. 查 K 线
curl "http://localhost:8000/api/v1/data/klines?symbol=BTCUSDT&interval=1m&start=2025-09-06T00:00:00Z&end=2025-09-07T00:00:00Z&limit=5"
# 期望：data 数组里至少 1 条 bar

# 5. 创建定时任务
curl -X POST -H "Content-Type: application/json" \
  -d '{"name":"btc_1m_every_5min","cron":"*/5 * * * *","symbols":["BTCUSDT","ETHUSDT"],"interval":"1m","enabled":true}' \
  http://localhost:8000/api/v1/data/schedules
```

## 6. 前端启动

```bash
cd frontend
npm install
npm run dev
# 浏览器打开 http://localhost:5173
# - /dashboard         行情看板
# - /data/downloads    K 线下载任务列表 + 新建
# - /data/schedules    定时任务管理
# - /market/BTCUSDT    行情详情（含 K 线 + WS 实时状态）
```

## 7. 实时推送验证

- 打开 `/market/BTCUSDT`，右上角应见 `● 实时`（绿色）
- 浏览器 DevTools → Network → WS → 查看 `/ws/market?symbols=BTCUSDT`，应每 100ms 收到 `{"type":"batch","items":[...]}`
- 注意：本环境的 Binance WS 推送在本机受网络限制，如仅网关不通，请确认 host 防火墙 / 代理设置

## 8. 常见失败与排查

| 现象 | 可能原因 | 修复 |
|---|---|---|
| alembic upgrade 报 `type "vector" does not exist` | 迁移未启 pgvector | 用 superuser 跑：`CREATE EXTENSION vector;` |
| health `db:false` | 5432 不可达 / 凭据错 | `Test-NetConnection 192.168.71.110 -Port 5432` |
| health `redis:false` | 6379 不可达 / db 错 | `redis-cli -h 192.168.71.110 -n 8 ping` |
| ticker 502 UPSTREAM_ERROR | 出网限制 / DNS | 设置 `BA_PROXY_URL` 走代理 |
| ARQ worker 不消费 | Redis URL 不一致 | 检查 worker 与 gateway 用同一 `.env` |
| K 线查询空 | 时间区间外 / 时区错 | 用 UTC ISO8601，如 `2025-09-06T00:00:00Z` |
| 前端 WS 一直 `○ 离线` | ws 反代未配置 | Vite 已配 `proxy: /ws -> ws://localhost:8000` |
