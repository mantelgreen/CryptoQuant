## 2. 各平台对本项目的可借鉴点

### 2.1 TradingView（行情图表标杆）
- **多窗格联动**：分时图 + 深度图 + 成交笔数 + 技术指标可拆分/联动缩放。
- **绘图工具层**：趋势线、斐波那契、图形识别可作为前端 `chart-toolset` 组件的参考。
- **指标生态**：Pine Script 的「指标即函数」思想可映射到后端 Python 因子注册表（`FactorRegistry.register`）。
- **学习点**：图表主体框架用 ECharts / lightweight-charts（TradingView 开源版）即可，避免自研。

### 2.2 Binance 官方 App / Square
- **行情看板**：自选 + 涨幅榜 + 资金费率榜 + 新币榜，是「主看板」的最小完整集合。
- **订单簿 + 大单成交笔数**：是「行情详情页」必备，建议我们的 `MarketDetail` 至少包含 ①蜡烛 ②深度热力图 ③逐笔成交 ④资金费率历史。
- **风险提示**：内置「波动 / 流动性 / 风险评分卡」——我们的指标卡可借鉴这种结构。

### 2.3 Coinglass（衍生品数据之王）
- **核心模块**：资金费率、多空比、爆仓地图、强平热力、持仓量变化、期权最大痛点。
- **我们 MVP 不做**：期权痛点。但 **资金费率、多空比、爆仓、持仓量** 这四项是「行情详情页」增强项，建议列为 v1.1 计划。
- **可视化范式**：所有衍生品指标都用 **堆叠面积 + 百分比 + 阈值带** 三件套，值得在 `IndicatorCard` 中预置该样式。

### 2.4 BigQuant（AI 因子研究标杆）
- **因子平台架构**：`因子 = Python 函数 + 输入/输出 Schema + 文档`，注册到「因子库」，可视化拖拽 + Notebook 两种用法并存。
- **ML 流程**：训练集 / 验证集 / 测试集切割、回测区间过滤、特征重要性、IC 分析、因子衰减，全流程白盒。
- **AI Studio**：自然语言生成因子与策略，平台会把生成的代码 commit 到一个「AI 草稿」分支，由用户确认后入库。
- **学习点**：①因子即代码（code-as-factor） ②数据集切割是平台一等公民 ③AI 生成结果落库并可追溯。

### 2.5 米筐 RiceQuant
- **回测引擎**：事件驱动 + 向量化双引擎，分层清晰（API 层 / 策略层 / 风控层 / 执行层 / 撮合层）。
- **绩效指标**：年化、夏普、Sortino、Calmar、最大回撤、Alpha/Beta、胜率、盈亏比、换手率——**必备**。
- **归因**：Brinson 模型做行业/风格归因，数字币场景简化为「币种贡献度 + 方向贡献度」。
- **学习点**：回测引擎一定要分 `Signal → Order → Fill → Portfolio → Metric` 五层流水线。

### 2.6 掘金量化
- **本地化执行**：策略跑在本地终端，平台做编排 + 监控 + 报告——给我们一个提示：**模拟交易 / 实盘的执行进程与 Web 平台解耦**，平台只下发策略包与配置。

### 2.7 VectorBT / VectorBT Pro
- **回测哲学**：向量化快、迭代式研究友好，适合「策略实验室」快速对比几十种参数组合。
- **我们**：把它放在 **因子 / 策略研究室的快速回测通道**，生产级回测仍用自研事件引擎（带撮合、滑点、手续费）。

### 2.8 QuantConnect (Lean)
- **算法实验室**：项目结构 = `Main.py + Algorithm + Universe + Alpha + Risk + Execution`，模块化典范。
- **数据 / 研究 / 回测 / 实盘** 四态共享同一份代码，是「同一策略多环境运行」的黄金标准。
- **学习点**：策略代码运行环境要支持 `research / backtest / paper / live` 四种 context。

### 2.9 Jesse
- **代码即策略**：路由 + 策略 + 指标全部 Python，调试体验好。
- **学习点**：策略文件即路由（`strategies/MyStrat/__init__.py`），路由文件约定 webhook 入口。

### 2.10 HummingBot
- **做市策略模板** + **多交易所适配层**——给我们一个提示：**交易所适配要做抽象层**（`ExchangeAdapter`），未来切 OKX / Bybit / Gate 不重写业务。

## 3. 共识结论：本平台要做出的差异化

1. **「LLM 驱动模拟交易」是独家卖点**：所有主流平台都没有「LLM 直接下单模拟盘并产出对比报告」这个能力。我们用 AgentScope 让 LLM 读行情 → 出决策 → 模拟撮合 → 写复盘，构成平台最具差异化的模块。
2. **「三路绩效对比」是叙事主线**：手动 vs 策略化 vs LLM-Agent，必须有统一的绩效归因与可对比的资金曲线视图。
3. **「Token 用量统计」是基础设施**：虽然小众，但能把 LLM 调用成本/收益显性化，是企业级落地的硬需求。
4. **「因子即代码 + AI 因子工坊」**：借鉴 BigQuant，但把 AI 生成因子作为一等公民，并把整个生命周期（生成 → 回测 → 衰减分析 → 入选因子库）打通。

## 4. 反例 / 不要做的事

- ❌ 不要自研图表内核：用 lightweight-charts / ECharts / Plotly 组合足以。
- ❌ 不要在 Web 主线程跑回测：永远走异步任务 + Redis 队列 + WebSocket 推送进度。
- ❌ 不要让 LLM 直接调交易所 API：LLM 只产「决策 JSON」，由 Execution Worker 校验后下单，避免 prompt 注入 + API 滥用。
- ❌ 不要把订单簿前端每 tick 渲染：聚合到 100/200/500 档 + 节流 100ms 重渲染。
- ❌ 不要在策略代码里硬编码交易所/标的：策略只认 `Symbol/Exchange/Timeframe` 抽象，下层用适配器映射。
