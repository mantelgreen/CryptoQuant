1. 前端框架使用vue3、tailwind css，需要明暗两个色的主题切换
2. 后端框架使用fastapi、postgresql+timescaledb+pgvector、大模型Agent框架使用Agentscope、使用redis作为消息队列、缓存，
3. 数据库信息如下

# 功能需求：
1. 需要有实时查看主要数字币行情看板
2. 需要选择数字币查看行情详情、分时图、订单簿等等，需要尽可能详细的行情图表，需要对比分析主流的行情应用
3. 需要能够一键下载K线数据，能够选择k线数据的时间范围和颗粒度（小时、30分钟、15分钟等等），并能够创建定时任务自动下载，需要考虑币安平台的下载数据限制
4. 需要有策略研究板块，对接大模型，创建策略，并进行回测，要有实时策略绩效图表、指标卡，对比分析其他平台的策略研究回测平台是怎么实现的
5. 需要有因子研究平台，实现基于机器学习的多因子回测，需要能够选择多个因子来喂数据，并且能够对数据进行训练数据、回测数据的切割装配，
6. 需要有对接大模型来实现因子的自动研究、设计策略组合，实现目标策略指标
7. 需要有模拟交易，对接大模型，由大模型来进行实时的交易模拟，并且要有手动的模拟交易，能够对比大模型、手动交易、策略化交易的绩效
8. 需要有系统对LLM调用的token消耗统计，所有模型的调用token消耗要汇总

# 性能需求：
1. 所有长时任务要异步，不能有卡顿现象
2. 大模型的调用也需要异步，不能有卡顿现象
3. 需要规避行情数据源对接口调用的限制，不能被封ip

# 其他需求：
1. 后台框架需要根据最佳实践来分层，不能把所有模块平铺，
2. 前台框架需要将组件拆分，能共用的组件需要拆出来给别的页面使用
3. 你需要对比分析类似平台的功能，来应用到我们的平台上，需要先写清楚系统设计方案，保存到doc目录下
4. 设计方案写完需要review一遍，补足并修复遗漏和逻辑错误，然后再开始开发
